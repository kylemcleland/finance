# finance

A private web app for two people to track shared expenses: monthly spending by
category, each expense allocated to **me** / **her** / shared, a running
contribution balance (who paid vs. whose share it was), and per-category trends.

Status: steps 1 and 2 of the build plan are done (data pull + classifier +
CSV export). The dashboard is next.

## How classification works

Each transaction gets a budget category and a `share_me` percentage (how much of
it is mine; the rest is hers). Layers run cheapest first and the first one that
answers wins:

1. **Rules** (`MerchantRule` table): your own overrides, e.g. "peloton" is
   Health, 100% me. Any correction you make becomes a rule.
2. **Plaid category** (`personal_finance_category`) mapped onto our smaller list
   in `src/lib/categories.ts`, or a keyword table for CSV imports that have no
   Plaid category. Shared categories (groceries, rent, utilities) default to
   50/50. Personal categories (coffee, shopping, personal care) use the account
   that paid: my card means mine, her card means hers.
3. **Claude** only for merchants nobody has seen before and that paid from a
   joint account. One call per merchant ever, cached in `MerchantCache`.
   Skipped when `ANTHROPIC_API_KEY` is not set.

Anything still unresolved is split 50/50 and flagged `needs_review`.

## Setup

```bash
npm install
cp .env.example .env     # local only; the cloud environment uses secrets instead
npm run db:push          # creates ./dev.db (SQLite)
npm run seed             # categories, three logical accounts, starter rules
```

Secrets, never committed: `PLAID_CLIENT_ID`, `PLAID_SECRET` (the Production
secret; the free Trial plan allows 10 real bank links), `PLAID_ENV=production`,
and optionally `ANTHROPIC_API_KEY`. After linking banks, also
`PLAID_ACCESS_TOKENS` so a fresh database can re-attach them.

## Getting transactions in

**From your real banks via Plaid** (works from a phone, no server needed):

```bash
npm run plaid:link -- --owner shared   # prints a plaid.com URL
# open the URL, log into the bank, then:
npm run plaid:link -- --finish         # stores the link, prints PLAID_ACCESS_TOKENS
npm run plaid:sync                     # /transactions/sync, resumable via stored cursor
```

`--owner` is whose money the linked accounts hold (`me`, `her`, `shared`);
that is how the app knows who paid. Each real bank link uses one of the Trial
plan's 10 permanent Item slots, so link each bank once. Plaid sandbox still
works for testing: set `PLAID_ENV=sandbox` and run `plaid:link -- --sandbox`.

**From a bank CSV**:

```bash
npm run import:csv -- --file samples/sample-transactions.csv
# real export: columns are detected by header; --negate if spending is negative
npm run import:csv -- --file ~/Downloads/chase.csv --account "Joint Checking" --negate
```

CSV accounts are matched by name; set each one's `owner` in the `Account` table.

## Classify and export

```bash
npm run classify         # classifies new rows, writes exports/transactions.csv
npm run classify -- --all   # re-run everything except manual corrections
npm run export           # just regenerate the CSV and summary
```

The summary printed at the end shows spend by category, what each person paid,
what was allocated to each, and the resulting balance.

## Sample data

`samples/sample-transactions.csv` is synthetic (generated by `npm run sample:gen`).
Replace it with a real export from your bank, with account numbers stripped,
so the dashboard is judged against real spending.
